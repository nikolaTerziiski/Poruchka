## 0. The three things that matter most

### 0.1 Bulgarian text has no brand typeface — the primary language is the undesigned one

This is the highest-impact finding in the audit, and it is invisible if you develop in English.

Queried Google Fonts directly for the subsets it will actually serve:

| Font | Role in the DS | Subsets served |
|---|---|---|
| **Bricolage Grotesque** | `--font-display` — every heading | `latin, latin-ext, vietnamese` — **no Cyrillic** |
| **Hanken Grotesk** | `--font-sans` — all body & UI text | `cyrillic-ext, latin, latin-ext, vietnamese` — **no basic Cyrillic** |
| JetBrains Mono | `--font-mono` | `cyrillic` ✓ |

`cyrillic-ext` is U+0460–052F (historic and minority-language glyphs). Bulgarian letters live in the
basic Cyrillic block **U+0400–045F**, which *neither brand font ships*.

Confirmed in the browser: rendering `Поръчка` through `var(--font-display)` measures **171.28125px**
— identical to the same string in `system-ui`. The fallback is total.

**Consequence:** every Bulgarian character in the product renders in the OS font (Segoe UI on
Windows). The display/body typographic contrast that `AGENTS.md` §8 prescribes *specifically to
avoid the generic "AI-generated" look* exists only for English visitors. The audience the product is
built for sees the one version with no typographic identity at all.

**Fix:** replace both faces with Cyrillic-covering ones and self-host via `next/font` (which also
removes the render-blocking CDN `@import` and the IP leak to Google). Candidates verified to carry a
real `cyrillic` subset: **Wix Madefor Display + Wix Madefor Text** (designed as a pair, warm and
humanist — closest to the current intent), or **Onest** / **Golos Text** (the latter designed
Cyrillic-first). Verify any replacement renders `Поръчка към доставчик` in the brand face before
accepting it.

### 0.2 Contrast is below WCAG AA across the core palette

Measured live against the tokens in `app/ds/colors.css`:

| Token pair | Measured | AA requires |
|---|---|---|
| white on `--accent` #1c7fc7 — **every primary button** | **4.28:1** | 4.5:1 |
| `--text-muted` #8c8273 on page | **3.54:1** | 4.5:1 |
| `--text-muted` on white card | **3.78:1** | 4.5:1 |
| `--text-faint` #b7ac9a on page | **2.09:1** | 4.5:1 |
| focus ring | **1.44:1** | 3:1 (SC 1.4.11) |
| input borders | **1.59:1** | 3:1 (SC 1.4.11) |

`--text-muted` alone has **54 usages** — every page subtitle, every table header, every hint. This is
not an edge case; it is the product's secondary text colour. Kitchen phones in poor lighting are the
actual usage context.

### 0.3 Every error the user can hit is shown in English JSON

`lib/api.ts:28` throws `` `API ${res.status}: ${body}` `` and all 23 catch sites do
`setError(cause instanceof Error ? cause.message : t.loadFailed)`. Because `api()` *always* throws an
`Error`, the `instanceof` branch always wins — **every carefully written Bulgarian fallback string in
the app is unreachable dead code.** A Bulgarian restaurant owner sees:

```
API 400: {"message":"Quiet hours start and end cannot be the same","error":"Bad Request","statusCode":400}
```

Supabase auth errors leak the same way on login, register and password reset.

## 1. Bulgarian copy — the semantic problems

The owner's requirement is that Bulgarian read as Bulgarian, not as translated English. It largely
does, but there is a consistent set of calques and one outright inversion.

### 1.1 Terminology drift — the same concept has four names

The central object of the product is called all of these, in shipping UI:

| Surface | Word used |
|---|---|
| Sidebar nav | **Планове** |
| Order-plans page title | **Планове за поръчки** |
| Dashboard empty-state CTA | **график** ("Създай график") |
| Items delete dialog | **графици** |
| Telegram bot | **Графикът** |
| Orders page | **Повтарящият се план** |

A non-technical user cannot tell whether "план" and "график" are the same thing. **Pick one canon and
apply it to the web app and the bot together.** Recommended: **план за поръчка** everywhere; retire
"график" entirely.

Same problem, smaller scale: `артикул` vs `стока` vs `продукт` for the thing you order — the Items
page uses two of them in adjacent lines, with a participle that doesn't agree
(`"Стоките, които поръчвате, всяка свързана с доставчик"`).

### 1.2 The quiet-hours inversion

The landing page renders quiet hours as their opposite:

> "Poruchka напомня на всеки час **в рамките на работното време**"

Quiet hours are the window in which the product is *silent*. Settings correctly calls them
**тихи часове**. The landing page describes the core promise backwards.

Worse, Settings' own help text instructs the user to do something the API rejects:

- `settings/page.tsx:67` — "Еднакъв начален и краен час изключва тихите часове."
- `me.controller.ts:38` — `if (dto.quietHoursStart === dto.quietHoursEnd) throw new BadRequestException(...)`

Follow the instruction, get an English 400.

### 1.3 Calques and register problems

| Current | Problem | Suggested |
|---|---|---|
| "потвърждава с едно **докосване**" | literal "tap"; BG UI verb is натискам | "с едно **натискане**" |
| "**Той докосва** Готово" | gendered subject + calque | "**Натиска** „Готово“" |
| "статуса **на живо**" | calque of "live" | "**актуалното състояние**" |
| "Цената е **нагоре с** X%" | calque of "price up X%" | "Цената е **с X% по-висока**" |
| "Маркирай като изпратена **другаде**" | unparseable on a button | "Вече е поръчана" |
| "Ескалирай / ескалация" | corporate-support jargon | "Уведоми {name}" / "Просрочени" |
| "пилота" (bare noun, 8×) | reads as *pilot (aviator)* | "пилотния период" |
| "Metro" (landing) vs "Метро" (app) | mixed scripts in one language | pick Cyrillic **Метро** |
| `“ … ”` in Bulgarian strings | English quotation marks | `„ … “` |

The Team page addresses every member as male throughout — "с него", "неговия Telegram", "неговия чат"
— in an industry where much of the staff will be women. Rewrite to avoid the pronoun entirely
("след като свържете профила в Telegram").

### 1.4 Formatting that is not localized

- Weekday abbreviations mix two- and three-letter forms; "Чет" is not standard (use **Чт**).
- A week spanning two months prints one month name: "Седмица 30–5 август".
- `"1 минути"` — fixed plural next to a free number input.
- Order totals print a bare number with an English decimal point — no lev, no BG grouping.
- Delivery problems render as the **raw database enum**: `SHORT`, `MISSING`, `DAMAGED`,
  `SUBSTITUTED` — while correct Bulgarian labels exist a few lines above in the same file.

## 2. Design — what feels off and why

The design system itself is sound: warm bone palette, a single azure accent, restrained radii, real
copy. The problem is **it isn't actually used**.

- **The spacing scale has zero usages.** Every gap and padding in the product is a magic number, many
  off the stated 4px grid.
- **128 raw-px font sizes against 26 token uses**, including 17 fractional values (`13.5`, `12.5`,
  `11.5`) that exist nowhere in the type scale.
- **"Something went wrong" is drawn seven different ways** across eight pages.
- **Six different loading treatments**, no skeletons, no spinner anywhere.
- **Three unrelated empty-state designs** for the same job.
- **Dashboard and Orders each ship their own summary-stat card**, disagreeing on every dimension.

Concrete visual defects:

- The landing page **scrolls sideways on every phone** — the hero grid is 43px wider than 375px, and
  `ReminderBubble` sets a hard 417px minimum (97px of overflow at 320px).
- The public top bar has **no mobile collapse**, contradicting `AGENTS.md` §7.
- `Table` sets `overflow: hidden`, so on a phone the Edit/Archive/Delete buttons are **clipped with
  no way to scroll to them** — 60% of the Order-plans table is unreachable.
- All seven app pages hard-code `padding: "32px 36px"` with no breakpoint — **72px of gutters on a
  375px screen**.
- On a 375px phone the Team row collapses its info column to 0px and **the person's name renders on
  top of the "Свържи Telegram" button**.
- The seven sidebar links have **no hover state at all** — the main navigation feels dead.
- `/terms` and `/privacy` render on **pure white** because `LegalPage` references `--surface-app`,
  a token that does not exist (verified: `getPropertyValue('--surface-app')` returns empty).
- The landing footer's **Условия / Поверителност links are `href="#"`** although both pages exist.
- The Active/Paused badge is **secretly a button** that pauses a plan on one click, with no
  affordance, no confirmation and no feedback.
- Reading the Terms you are *required* to agree to **wipes the registration form**.
- Notifications asks a restaurant owner to **hand-type an IANA timezone string** into a text box.

## 3. Structure — is it simple enough for the audience?

- **Three of the seven sidebar entries read as "orders"** to a restaurant owner (Календар, Поръчки,
  Планове), and one names a data model rather than an outcome. Group the sidebar into
  *what's happening now* vs *setup*, and rename to outcomes.
- **The calendar is a read-only picture.** Chips carry an `orderRunId` but are plain `div`s — seeing
  a due order gives you no way to act on it.
- **The one first-run call to action lands on a disabled button** with an unclickable hint, so a new
  account dead-ends at step one. There is no `/onboarding` route despite `AGENTS.md` §6 specifying one.
- **Nothing warns that reminders cannot be delivered when nobody has linked Telegram** — the product
  silently does nothing, which is the worst possible failure for a reminder tool.
- **The owner is auto-named with their email address** and no screen can rename a person.
- **Deleting a supplier that has items always fails**, the dialog stays open, and the error paints
  *behind* the modal backdrop.
- Creating an order plan asks for **eight decisions at once**, three of which a new owner has no
  basis to answer.
- The responsible-person picker **hides whether that person can actually receive a reminder**.

## 4. Accessibility

- **No visible keyboard focus indicator on any button** — the inline `boxShadow` overrides the global
  `:focus-visible` ring, and the global rule also kills the outline.
- **`Dialog` has no accessible name, no Escape handler, no focus trap, no initial focus, no focus
  restore** — every modal is a keyboard and screen-reader dead end. A stray backdrop click silently
  discards a half-filled 12-field form.
- **15 `<Field>` instances omit `htmlFor`**, so every control in the New-order-plan, Supplier-
  confirmation and Receive-delivery dialogs is announced with no name.
- **Not one `aria-live` region exists in `apps/web`** — a screen-reader user never learns a save
  succeeded or failed.
- **The mobile drawer is only translated off-screen**, leaving 13 invisible focusable controls ahead
  of the page content.
- **The agree-to-terms checkbox shows nothing when focused** (its real input is `opacity: 0`).
- **No `autocomplete` attribute anywhere**, so password managers cannot fill login or register.
- The Active/Paused toggle's `aria-label` is **inverted** — an active plan announces "На пауза".
- No `<main>` landmark on the landing page or any auth page; no skip-to-content link.
- Landing navigation uses `<button onClick={router.push}>` instead of links — absent from the screen
  reader's link list, and cannot be opened in a new tab.
